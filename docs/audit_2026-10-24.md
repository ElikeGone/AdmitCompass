## 2. API endpoints

## 4. Where the UI overwhelms the user
1. **Dashboard length:** 2,662 words and 76 controls on one page. Five numbered sections plus "Saved programs" and a link row to "Older views".
2. **Application workspace:** 40 tasks in 4 phases, all shown expanded. Each task is a full sentence. This is the largest block on the page.
3. **H-1B employer list:**
   - Each employer gets an occupation × city breakdown line, e.g. "307 · product management · Seattle; 100 · … ".
   - The list repeats across program tabs.
   - It's dense for the main question ("is this realistic for me?").
4. **Program fit:**
   - Per program: AI rationale, 5 "Supported by evidence" claims, tradeoffs, analyst reasoning, source excerpts.
   - Facts are repeated in sections 3 and 4.
5. **Two parallel result UIs:** the dashboard and "Older views" (`#/results/...`) show overlapping content: shortlist, roadmap and evidence. Users can't tell which is canonical.
6. **Explore:**
   - 30 cards, 1,658 words, before any filter is applied.
   - Badges for cost source, rank and estimates compete on each card.
7. **Agent trace:**
   - 60 events of tool-level detail: `search_programs(stem_designated=true max_cost_of_attendance=135000 states=)`.
   - Good for graders; noisy for applicants. It isn't labeled as a technical view.

## 5. Malformed or raw serialized values shown to users
- No `[object Object]`, `undefined`, `NaN`, `null`, `None` or JSON fragments render on any route (all `<details>` opened).
- **Raw field path in UI** (evidence page, "Automatic safeguards"): `unsupported_claims_flagged[4]: Pathway Matcher says…`. This is an internal schema path, not a label.
- **Raw identifiers in the trace:** `get_program_overview(program_id=mit-sloan-mba)`, and an empty `states=` argument rendered as-is.
- **Unformatted money in model text:** "Verified tuition is $91892". Agent prose isn't number-formatted, while the UI elsewhere shows "$91,892".
- **Payload only, not rendered:** `/api/demo` → `events[].detail.error` contains a raw Pydantic message ("2 validation errors for PathwayOutput … [type=value_error"). The UI correctly shows "Answer failed format checks — retrying", but anyone inspecting the API sees the raw text.

## 6. Implied but not implemented
- **"International Applicants" nav (`#/intl`):** renders the homepage again (`renderHome("intl")`), not a dedicated international screen.
- **Accounts:**
  - Copy says "Save programs, your profile and roadmap progress to your account".
  - Accounts are **off by default** (`accounts_enabled: false`), so saving and progress are browser-only.
  - The dashboard's "Saved programs" works through `localStorage`.
- **Cost per run:** shown as "cost unknown (no published gpt-6-luna price)". Dollar tokenomics are hypothetical only.
- **School-level visa sponsorship:**
  - The section title "Visa sponsorship" suggests a school answer; it is always "No school-level evidence" (0/28).
  - The real content is employer H-1B history.
- **Columbia and other discovery-tier programs:** shown in Explore beside core programs but can't be shortlisted ("detailed" programs only).
- **Live analyses:** capped at 3 per server (`live_runs_allowed: 3`). In the review/mock build, live runs are refused, so "Find my pathway" ends at the sample.
- **Deadline awareness:**
  - The workspace says "Week 1: diagnostics", but Round 1 deadlines it lists (e.g. MIT 2026-09-29, Booth 2026-09-15, Fuqua 2026-09-30) **have already passed** as of 2026-10-24.
  - There's no past-deadline logic in `frontend/app.js`.

## 7. Run-status, validation and safety risks for the rubric
1. **The featured demo run is `completed_with_violations`** (row: App works; row: Safety credibility).
   - Its one flag is a documented false positive from the old guarantee rule, since fixed.
   - The flagship screen shows an outdated safeguard with a caveat note.
2. **Demo token numbers are partly cache-replayed** (row: Tokenomics):
   - requests 1–9 matched an earlier run, 8 of them under 1 s;
   - the UI says so, but the headline usage (105,041 input, 64,600 cached) mixes cached and fresh.
   - The clean measured runs are in `experiments/tokenomics/clean_runs_analysis.md`; the demo shows none of them.
3. **Most clean runs end `completed_with_violations`, and two hit `stopped_budget` at cap 20** (row: App works):
   - documented in `docs/run_variability.md`;
   - graders may read the status as failure unless it's explained;
   - shortlists vary between runs.
4. **Impact + metrics (5 pts):** no real user session or quote. Flagged as a half-points risk in `docs/evidence_index.md`.
5. **Motivation (8) and novelty (21):** ChatGPT comparison outputs aren't collected; comparison table placeholders remain.
6. **Report design (2) and slides (8):** `report.html` and `slides.html` don't exist.
7. **Teaching staff can run it (5):**
   - not pushed to GitHub, so the fresh-clone test hasn't been run against the real URL;
   - a stray file `deliverables/screenshots$1.png` (mangled path) sits in the tree.
8. **Stale-date correctness:** past Round 1 deadlines are shown without a "passed" marker. This could read as bad advice in a demo.
9. **Tokenomics:** no official gpt-6-luna price, so every dollar figure is hypothetical. That's an acceptable but explicit limitation.
